# 人力材料分析撰写

## 何时使用

- payroll.xlsx（工号/姓名/应发/实发…）+ attendance.xlsx（工号/姓名/应出勤/实出勤）+ roster.xlsx（工号/姓名/部门）
- → 人员比对表 + 部门汇总 + HR 简报草稿 + 机器可读 hr-report.json

## 用法

```
python scripts/hr_compare.py --payroll p.xlsx --attendance a.xlsx --roster r.xlsx --outdir out/ [--no-mask]
```

三表均可选（至少一张）；列名按关键词识别（工号/员工编号/员工号/编号、姓名、部门、应发、实发、应出勤、实出勤、身份证/银行卡/手机/电话）。退出码：0=完成（冲突/数据质量问题属于分析发现，不算失败），2=输入错误（未提供任何表/文件损坏/**缺少工号列**）。

## 规则（脚本保证）

- 按**工号**关联；每张提供的表必须有工号列，否则**报错退出**，绝不以 0 人静默成功
- 表内工号重复：内容一致 → 去重计入并单列；**内容冲突 → 不挑行不丢行**，该人员标注"工号冲突"、冲突字段留空、**不计入部门汇总**，明细（来源文件+行号+各字段值）写入「重复工号」sheet 与 hr-report.json
- 姓名跨表不一致 → 显式标注；**仅当提供了考勤表**时：薪资有而考勤无 → `缺考勤记录`，考勤有而薪资无 → `缺薪资记录`
- 缺勤天数 = 应出勤 − 实出勤（手工可复算）；**未提供考勤表时不做缺勤结论**（不默认满勤、不写"已核查缺勤 0 天"）；考勤表缺应出勤/实出勤列时明确"缺勤不可计算"
- 金额/天数**为空、不可解析（如 N/A）、非有限数（如 NaN/inf/1e400）、公式无缓存值** → 逐人列入"数据质量"列与 hr-report.json，**不按 0 计入合计**
- 工号为空的行 → 「未关联行」sheet 单列（不静默丢行）；合计/总计行剔除汇总并留痕
- 汇总（部门人数/应发合计）**剔除合计行**；应发合计仅计入无冲突且应发为有限数值的人员；薪资表缺应发列时合计留空不按 0
- 输出文件中身份证/银行卡/手机号列默认脱敏为 `■`，脱敏清单写入 `mask-manifest.json`（--no-mask 关闭；敏感值不进入 hr-report.json/未关联行摘要/重复工号明细）

## 输出（outdir/）

1. `compare-report.xlsx`：sheet「人员比对」（工号/姓名(薪资)/姓名(考勤)/部门/应出勤/实出勤/缺勤天数/应发/实发/异常/数据质量/冲突明细/敏感列脱敏）+ sheet「重复工号」（来源文件/表/工号/行号/判定/字段值）+ sheet「未关联行」
2. `roster-summary.xlsx`：sheet「部门汇总」（部门/人数/应发合计，仅无冲突人员）+ sheet「汇总说明」（汇总范围/应发口径/考勤口径）
3. `draft.docx`：HR 分析简报草稿（人数与汇总范围、考勤口径、异常与数据质量问题计数均由计算值填充，明确列出冲突排除范围）
4. `hr-report.json`：机器可读汇总（people_total/in_summary/excluded_conflict、conflicts 含文件行号字段值、dropped_rows、data_quality、attendance_provided/total_absence 等）
5. `mask-manifest.json`：脱敏列清单

## 依赖

Python 3.9+，openpyxl、python-docx。
