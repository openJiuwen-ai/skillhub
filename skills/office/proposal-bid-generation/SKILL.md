# 方案与标书生成（要求响应矩阵 + 可追溯合规）

## 何时使用

- 招标文件（docx/md/txt）+ 资质材料目录 → 响应矩阵 + 投标草稿 + 缺口清单
- 用户要求"根据招标文件做响应矩阵/标书草稿/看我们缺什么资质"

## 用法

```
python scripts/bid_matrix.py --tender tender.docx --quals quals_dir --outdir out/
# 可选：--company "投标主体名称"（用于证据主体一致性核验）
```

## 输出（outdir/）

1. `response-matrix.xlsx`：逐条 {条款编号, 招标要求, 响应状态, 证据文件, 匹配词, 原因/说明, 条款出处}
2. `response-matrix.json`：机器可读明细（每条款 status/reason/证据摘录/候选/警示，含出处与续行标记）
3. `gaps.json`：缺口条款（含否定/过期证据原文）与待确认条款清单
4. `bid-draft.docx`：投标响应草稿（有证据条款引用文件与原文摘录并要求人工复核；缺口标【待补充-缺口】；待确认标【待确认-原因】）
5. `report.json` / stdout：解析模式（numbered/paragraph_fallback/table 组合）、条款数、responded/needs_confirmation/gaps 计数、前言跳过数、续行/表格条款数、资质可读性统计

## 条款解析（脚本保证）

- 编号行（第X条 / 一、 / 1. / （一））为条款起始；**短条款（如"4. 须盖章"）不做长度过滤，全部保留**
- 无编号的后续行并入上一条款（续行），条款带 `continued` 标记
- 首个编号行之前的内容计为前言跳过并在报告计数，不混入条款
- 无编号文件按段落回退：每个非空段落各成一条虚拟编号条款，报告注明 `paragraph_fallback`
- docx 表格逐行成条（首行识别为表头时跳过），出处如 `docx:表1行2`
- 每条条款记录出处（txt:行N / docx:段落N），xlsx 与 json 均可回溯

## 证据判定（脚本保证）

- **关键词只用于检索候选，不决定满足**：泛化词（公司/项目/合同/万元/证书/认证/预算等）先从条款文本剔除；纯数字不作证据关键词
- 条款含字母数字标识（如 ISO9001/PMP）时，肯定证据必须命中该标识，防止近邻资质（如 ISO27001）误配
- `responded`：仅当资质文件**内容**中出现不含否定/过期表述、主体可核验的肯定陈述（记录文件+原文摘录）
- `gap`：无有效证据；或材料中出现否定表述（未取得/尚未/不得宣称…）；或证据过期/失效（已过期/吊销/注销…）——否定/过期原文保留在矩阵与 gaps.json
- `needs_confirmation`：仅文件名命中（内容不可读或 pdf 等不支持提取的格式）；证据主体含第三方公司名且未提供 `--company` 或与 `--company` 不一致；肯定证据与否定/过期/主体问题并存（冲突待核）
- 空资质目录 → 全部 gap，仍输出完整矩阵供补齐

## 诚实边界

- 草稿**不自动承诺资格满足**：responded 条款只列证据并要求人工复核有效期、主体与适用范围
- 不虚构业绩、资质、人员证书；引用证据文件路径真实存在（相对资质目录）
- 主体一致性仅按 `--company` 与句内公司名做字符串级核验，不能替代人工审验

## 依赖

Python 3.9+，python-docx、openpyxl（资质 .docx/.xlsx 内容提取与矩阵输出）。
