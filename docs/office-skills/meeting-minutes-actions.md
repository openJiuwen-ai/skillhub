# meeting-minutes-actions 交付说明

会议文字稿 → 会议纪要 docx + 待办追踪 xlsx + ASR 存疑/冲突清单：解析带时间戳/说话人的转写稿，识别本期新增行动项，全量承接上期待办（保留原编号），生成两份内容完全一致的可编辑交付文件。

## 能力边界

| 场景 | 是否支持 |
|---|---|
| 带时间戳转写稿（`[HH:MM] 发言人: 内容` / `HH:MM 发言人：内容`）+ 上期待办 xlsx | 是（核心场景） |
| 无时间戳/无说话人转写 | 是，按行号定位，来源标注 `L行号@无时间戳` |
| 上期待办全量承接（含受阻/暂缓/已取消），保留原编号，新增项顺延（A01–A04 → A05 起） | 是 |
| 有效提及且明确说"已完成/办结" → 已完成（备注注明据某时点汇报、未独立核验） | 是 |
| 提及未说完成 / 未提及 → 状态原样保留，不推断为已完成或进行中 | 是 |
| 否定式引用（"这不是A01"、"本期没有讨论A01"）不算提及、不算新进度 | 是 |
| 对上期待办的状态汇报句不重复识别为新增任务 | 是 |
| 责任人：句中"X 负责/牵头…"模式（剔除 由/请/让 等引出词与代词）、发言人自述承诺（我负责/我会…） | 是 |
| 主持人安排但无人认领 / 无自述 → 责任人 `待确认`，不以主持人代填；截止缺失同样 `待确认` | 是 |
| 同句两个及以上不同金额/百分比（如 12万元 vs 15万元）→ 冲突双方数值完整保留，不选择、不定稿 | 是（写入 asr-issues.json 与纪要"待确认事项"） |
| 金额/百分比类数字 ASR 待核清单（不自动改写） | 是 |
| 纪要 docx 行动项表与追踪 xlsx 9 列逐行完全一致（含来源时间戳）；两次运行输出一致 | 是 |
| 上期 xlsx 损坏 | 降级：stderr WARNING，无承接继续生成本期新增，退出码 0 |
| 转写文件缺失/不可读 | 退出码 2，不产出文件 |
| 语义级任务改写、委婉语/反语的深层理解、会议主题自动命名 | 否（确定性规则层，不做推断改写） |

## 安装与依赖

- Python 3.9+
- python-docx（MIT）、openpyxl（MIT）
- 标准库：argparse / json / re / os / sys

技能包结构：

```text
meeting-minutes-actions/
├── SKILL.md
└── scripts/minutes_actions.py
```

## 用法

```bash
python scripts/minutes_actions.py --transcript t.txt \
    [--prev-actions prev.xlsx] --outdir out/
```

上期待办 xlsx 约定列 `编号/责任人/任务/截止/状态`（兼容 `行动项编号/负责人/事项/截止日期` 别名）。

## 输出（outdir/）

- `minutes.docx`：一、会议结论（决议句+时间戳 + **本期进展摘要/未决事项摘要**，前置完成更新与预算冲突）；二、行动项表（与 xlsx 同构 9 列）；三、待确认事项（数字冲突/待确认责任人截止/未提及项）；四、说明
- `actions.xlsx`：`待办追踪` 表，列为 `编号/责任人/任务/截止/状态/类型(上期承接|本期新增)/来源时间戳/本期是否提及/备注`；未提及项来源为"明确未讨论"语句时间戳或"上期"
- `asr-issues.json`：`number`（金额/百分比待核）与 `conflict`（同句冲突，`values` 双方保留）条目
- stdout：JSON 汇总（minutes/actions/n_actions/carried/new/decisions/asr_issues/conflicts）

## 版式（视觉交付）

针对 native-qa/meeting-minutes-layout-review.json（主控 WPS 实机观察，2026-10-14）的版式修复：9 列表格改**横向页面**并按内容分配列宽（任务 7.0cm、备注 5.5cm，编号/状态等窄列 1.5–1.8cm），表格字号 9pt，**表头行跨页重复**且单行不跨页拆分，提升可读性；会议摘要新增“本期进展摘要/未决事项摘要”，将上期完成更新与未解决预算冲突前置到行动项表之前，不再只埋在表格末尾。字段、来源、七个行动项及原状态均保持不变。**本交付未声称已完成 WPS 实机复验**（由主控执行）。

## 退出码

- 0：完成（含空转写、上期文件损坏降级）
- 2：转写文件缺失/不可读，不产出文件

## 验收依据与测试

对应冻结基准 `benchmarks/meeting-complex`（prompt.txt/expected.json，2026-10-14 冻结）与基线"周复盘/跨周状态承接"方向。黑盒测试位于 `tests/office_skills/test_meeting_minutes_actions.py`（7 项，独立推导预期值）：

1. 正常：两期承接——有效提及且完成→已完成（原始表述保留）、未提及→受阻/暂缓原样、明确未讨论语句作来源证据、编号顺延、责任人三种认定路径、历史汇报句不重复立新项、docx/xlsx 逐行一致、两次运行一致
2. 复杂（冻结基准同题）：expected.json 9 项检查逐条断言——A01 受阻未被提及且不与新询价表混同、A02 据汇报完成且附件情况按原话保留不宣称独立核验、A03 暂缓、A04 已取消、新询价表（林舟/2026年10月16日/09:02）、预算核对（责任人截止均待确认/09:04）、演示材料（林舟/待确认/09:05）、12万元 vs 15万元 冲突双方保留（09:03）、两文件编号及内容一致；无任何行以"主持人"充当责任人
3. 复杂版式（独立验证）：横向页面、9 列、跨页重复表头、任务列宽 > 编号/状态列、表格字号统一 9pt、摘要位于表前且含 A02 已完成与 12万元/15万元 冲突；同时确认 7 项与原状态未被改动
4. 异常：转写缺失退出 2；空转写产出空表与占位段落退出 0；上期 xlsx 损坏 WARNING 降级；无上期且无时间戳仍可解析并按行号定位

在仓库根目录运行：

```bash
python -m pytest tests/office_skills/test_meeting_minutes_actions.py --basetemp <任务目录下唯一临时目录>
```
