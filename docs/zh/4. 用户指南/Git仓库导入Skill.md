# Git 仓库导入 Skill

Git 仓库导入用于从公开仓库批量同步 Skill，适合团队集中维护多个 Skill 的场景。

## 适用场景

- 一个仓库中维护多个 Skill 目录。
- 希望通过固定分支或标签同步 Skill。
- 希望减少手工逐个上传的成本。
- **同一仓库的不同技能根目录**，由不同用户分别接入（每人填写各自的 `skills_subpath`）。

## 基本流程

1. 登录 openJiuwen Agentic Hub。
2. 进入个人中心的 Git 源管理入口。
3. 填写仓库地址、分支或标签、Skill 子路径（可选；提交前会归一化路径）。
4. 创建 Git 源并等待后台同步完成。
5. 在列表中查看同步状态；需要时可「再次同步」。

## 仓库要求

- 仅支持服务端可访问、可安全解析的公网 `http://` 或 `https://` 克隆地址。
- 不支持 SSH/SCP 地址，也不支持 URL 中携带用户名或密码。
- 不允许访问本机、内网、链路本地、保留地址，以及 `.localhost`、`.local` 等本地域名。
- 主机名无法解析或解析结果包含不安全地址时，服务端会拒绝创建或同步。
- Skill 子目录结构需要符合发布校验规则。
- 每个 Skill 应有明确名称、版本和描述。

这些限制在创建 Git 源和每次同步前都会执行，用于避免服务端访问非预期网络目标。

## 同步与跳过

- 再次同步时，若某个 Skill **目录内容未变**，会跳过发布（即使仓库其它路径有新 commit）。
- 仅当该 Skill 目录内容变化时才会更新市场中的对应资产。

## 删除 Git 源

- 删除 Git 源注册时，会 **一并永久删除** 该源已导入的全部 Skill（含对象存储中的包）。
- 删除后可再次以相同仓库、分支与技能根路径重新注册。
- 同步进行中不可删除。

## 常见问题

- 仓库不可访问：检查仓库是否公开、地址是否正确、服务端网络是否可达。
- 部分 Skill 导入失败：检查失败项的目录结构、版本号和 `SKILL.md`。
- 同步后未上架：导入成功后仍需经过审核流程。
- 提示已被全局注册：同一「仓库 + 分支/tag + 技能根路径」只能有一条源；请确认路径是否填错，或联系已注册用户。
- 删除后仍无法再接入：确认删除已成功（会释放去重槽位）；若仍有同名 Skill 残留，再次同步会尝试回收无绑定/孤儿绑定的同名资产。
