# 角色与权限

本文说明 SkillHub 中 **普通用户、创作者、审核管理员、系统用户** 的权限划分，以及 **不同审核状态下 Skill 的展示与操作规则**。

## 角色概览

| 角色 | 识别方式 | 典型能力 |
|------|----------|----------|
| **访客（未登录）** | 无 Bearer Token | 浏览公开市场、查看详情、下载已通过版本、浏览量 +1 |
| **普通用户（已登录）** | OAuth 登录 | 访客能力 + 点赞/收藏、个人中心、发布 Skill |
| **创作者** | 已登录且为某 Skill 的 `publisher_id` | 普通用户能力 + 管理自己的 Skill/版本、查看待审版本与审查详情 |
| **审核管理员** | 登录名在 `MARKET_REVIEW_ADMIN_USERNAMES` 中 | 创作者能力 + 待审核列表、审核通过/驳回、审核历史、审计日志、查看全部待审/驳回版本 |
| **系统用户** | 请求携带有效 `X-System-Token` | 服务端间调用：批量导入、系统发布（跳过普通用户审核链路）等；**禁止** 写入浏览器或客户端 |

> 审核管理员名单由实例管理员在 `.env` 配置，与 GitCode/GitHub **用户名精确匹配**。系统 Token 用户同时视为审核管理员（`is_market_moderation_admin=true`）。

## 审核状态与可见性

Skill（含 Swarm Skill）的版本级审核状态：

| 状态 | 代码 | 公开市场列表 | 公开市场详情/下载 | 创作者个人中心 | 审核员 |
|------|------|:------------:|:-----------------:|:------------:|:------:|
| 审核中 | `PENDING` | 不展示该版本 | 不展示（对外仍显示上一已通过版本） | 可见，含状态 | 可见，可审核 |
| 已通过 | `APPROVED` | 展示 | 可下载 | 可见 | 可见 |
| 已驳回 | `REJECTED` | 不展示该版本 | 不展示 | 可见，含驳回原因 | 可见 |

### 聚合规则（资产级）

- 市场 **Skill 卡片上的版本号**：对普通访客为 **最新已通过审核的对外版本**（`public_latest_version`）
- 创作者在个人中心看到的 `latest_version` 可能 **高于** 市场展示版本（存在待审新版本时）
- 若 Skill **从未有过已通过版本**，则 **不会出现在公开市场**，仅在创作者个人中心与审核待办中可见

### 发布阶段（系统审查，可选）

当 `MARKET_SKILL_REVIEW_ENABLED=true` 时，普通用户发布的 Skill 会经历：

```
发布 → 系统审查（publish_result=reviewing）
     → 人工审核（publish_result=pending_moderation，moderation_status=PENDING）
     → 上架（publish_result=publish_success，moderation_status=APPROVED）
```

| 阶段 | 人工审核 | 说明 |
|------|:--------:|------|
| 系统审查中 | 不可用 | 须等审查结束 |
| 系统审查失败 | — | 发布失败（`publish_failed`），不进入人工审核；可查看审查详情后重新发布 |
| 系统审查通过 | 可用 | 进入人工审核队列 |
| 系统审查关闭（默认） | 可用 | 跳过后直接进入 `pending_moderation` |

**例外**：

- **系统 Token 发布**（`X-System-Token` 对应 `SYSTEM_ADMIN_USER`）：Skill 直接 `APPROVED`，跳过系统审查与人工审核
- **非 skill-like 类型**（如 `tools`、`mcp` 等插件）：不受 Skill 审核链路约束（若实例启用）

---

## 互动规则

- **点赞、收藏**：须登录；**不能** 对自己的 Skill 点赞或收藏
- **浏览量**：无需登录，每次访问详情可 +1
- **通知**：审核结果、待审提醒等仅发送给相关用户（发布者 / 审核员）

---

## 下载与版本解析

| 调用方 | 未指定 version | 指定 version |
|--------|----------------|--------------|
| 公开市场用户 | 解析为 **最新已通过版本** | 仅当该版本 `APPROVED` 时可下载 |
| 创作者本人 | 可查看全部版本详情 | 含待审/驳回版本 |
| 审核管理员 | 同创作者 + 待办筛选 | 含待审/驳回版本 |
| 系统 Token | 按 API 权限 | 按 API 权限 |

## 配置审核管理员

实例管理员在 `.env` 中设置：

```env
MARKET_REVIEW_ADMIN_USERNAMES=alice,bob
# 或 JSON 数组：["alice","bob"]
```

修改后须 **重启 marketplace 服务**。用户须使用 **与配置完全一致** 的 OAuth 登录名；登录后调用 `/api/v1/auth/me`，若返回 `is_market_moderation_admin: true`，前端侧栏即显示审核菜单。

> 审核管理员不能审核自己发布的 Skill。验证完整流程时必须使用两个不同账号：一个账号发布，另一个已配置为审核管理员的账号执行通过或驳回。

## 审核管理员操作

登录后个人中心侧栏显示「待审核」「审核历史」「审计日志」。

- **待审核**（`/profile?tab=pending`）：展示 `PENDING` 状态的 Skill，进入详情页执行审核。
- **审核通过**：该版本对外可见；新版本通过后市场最新对外版本更新。
- **审核驳回**：**必填驳回原因**；发布者收到通知，须修改后发布新版本。
- **规则**：系统审查中的 Skill 人工审核不可用；已通过的版本不可驳回；已驳回版本可由审核员改判通过以恢复上架，或等待发布者发布新版本。
- **审核历史**（`/profile?tab=audit`）：查看本人历史通过/驳回记录及原因。
- **审计日志**（`/profile?tab=audit-log`）：查询平台全量操作审计，支持筛选，可导出 CSV（单次上限 5 万条）。
- **系统审查详情**（`/profile/plugins/:assetId/versions/:version/review`）：展示规则扫描、AI 语义复核等维度结果，发布者与审核员均可查看。
