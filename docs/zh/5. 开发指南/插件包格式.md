# 插件包格式

本文面向通过 CLI 制作和发布 SkillHub 资产的创作者与开发者，汇总公共规则并提供分类型规范入口。实际校验以当前 CLI 和 marketplace 服务端实现为准。

## 支持类型

| 类型 | `runtime.type` | 适用场景 | 详细规范 |
|---|---|---|---|
| Tools | `tools` | 以 Python wheel 交付的本地工具集合 | [Tools 格式](./插件类型格式/Tools格式.md) |
| MCP Stdio | `mcp-stdio` | 通过标准输入输出启动的 MCP Server | [MCP Stdio 格式](./插件类型格式/MCP-Stdio格式.md) |
| RESTful API | `restful-api` | 将外部 HTTP API 描述为可调用工具 | [RESTful API 格式](./插件类型格式/RESTful-API格式.md) |
| Skill | `skill` | 单 Agent 的指令、脚本与参考资源 | [Skill 与 SwarmSkill 规范](./Skill与SwarmSkill规范.md) |
| SwarmSkill | `swarmskill` | 多角色协同执行的 Skill | [Skill 与 SwarmSkill 规范](./Skill与SwarmSkill规范.md) |

## 如何选择类型

- 需要分发 Python 实现并安装 wheel：选择 `tools`。
- 已实现 MCP Server，且由宿主进程通过 stdio 启动：选择 `mcp-stdio`。
- 能力由远程 HTTP 服务提供：选择 `restful-api`。
- 主要内容是给 Agent 使用的指令和资源：选择 `skill`。
- `SKILL.md` 中包含多角色协作定义：选择 `swarmskill`。

## 开发目录与发布 ZIP

开发目录用于编写和校验源码；发布 ZIP 是 `pack` 命令生成的交付物。两者不一定相同：

- `tools` 开发目录包含 `src/` 和 `pyproject.toml`，发布 ZIP 包含构建后的 `dist/*.whl`。
- `mcp-stdio` 与 `restful-api` 保留经过忽略规则过滤后的目录内容。
- Skill 与 SwarmSkill 可以只维护 `SKILL.md` 及其资源；CLI 发布时会补齐市场所需元数据。

不要手工假设 ZIP 内部结构，推荐始终通过 CLI 打包。

## 公共元数据

非 Skill-like 类型在根目录使用 `plugin.yaml`：

```yaml
name: example-plugin
version: 0.0.1
display_name: Example Plugin
description: Describe what the plugin provides.
runtime:
  type: tools
metadata:
  author: your-name
  tags: [example]
compatibility:
  python: ">=3.11, <3.14"
```

公共约束：

- `name` 使用小写字母、数字和连字符，并以小写字母开头。
- `version` 通常使用 `x.y.z`；服务端也支持 7 位小写 Git commit 格式。
- `display_name`、`description` 和 `metadata.author` 不能为空。
- `metadata.tags` 必须是非空字符串数组。
- 非 Skill-like 类型必须提供符合 PEP 440 的 `compatibility.python`。

Skill 与 SwarmSkill 的元数据以 `SKILL.md` 为核心，详见对应规范。

## 公共文件规则

- 发布物为 ZIP 文件，当前原始上传和累计解压上限均为 512MB；包内不得包含绝对路径或越出根目录的路径。
- CLI 会忽略 `.git`、`.venv`、`venv`、`__pycache__`、`out`、`__MACOSX`、`*.pyc`、`*.pyo` 和 `*.egg-info` 等内容。
- 非 Skill-like 类型必须提供 `README.md`。
- `icon.png` 为可选展示图标。
- `pack` 会同时生成 ZIP 和同名 `.sha256` 文件。CLI 发布会自动计算并发送校验和；直接调用发布 API 时必须提供 `X-Checksum-SHA256`。

## 标准 CLI 流程

```text
init → validate → pack → publish
```

```bash
openjiuwen-plugin init example-plugin --type tools
openjiuwen-plugin validate example-plugin
openjiuwen-plugin pack example-plugin --output out
openjiuwen-plugin publish --file out/example-plugin-0.0.1.zip \
  --market-url http://localhost:8100 \
  --token <token>
```

Skill 与 SwarmSkill 也可以使用 `jiuwen-teamskills`。发布不含 `plugin.yaml` 的 Skill-like 工作区时，需要通过 `--version` 提供版本号。

用户令牌和系统令牌互斥，不要将真实令牌写入文档、插件包或版本库。
