# 升级说明

本文提供 SkillHub 升级前后的检查清单。具体版本变化以仓库根目录 [CHANGELOG.md](../../../CHANGELOG.md) 为准。

## 升级前检查

1. 备份 MySQL 数据库。
2. 备份对象存储中的 Skill 包、图标和检索索引。
3. 保存当前 `.env`、`.env.docker`、`skill-runner.env.example` 派生配置。
4. 阅读目标版本的 `CHANGELOG.md`，重点关注 Breaking Changes、数据库脚本和环境变量变化。
5. 确认前端、marketplace、skill-runner 镜像或进程版本一致。

## 数据库变更

数据库脚本位于仓库 `sql/` 目录。执行前应确认：

- 当前数据库版本。
- 目标脚本是否已在测试环境验证。
- 回滚策略是否可执行。

## 配置变更

升级时重点对比：

- `.env.example`
- `skill-runner.env.example`
- Docker 启动参数
- OAuth、对象存储、检索和在线体验相关配置

### 常见版本迁移点

| 变更类型 | 如何检查 |
|----------|----------|
| 新增环境变量 | 对比新旧 `.env.example`，将新增项复制到你的 `.env` |
| 废弃环境变量 | CHANGELOG 中标注为 deprecated 的变量可以移除 |
| 默认值变化 | 检查 CHANGELOG 中是否提到默认值变更，评估是否需要显式设置 |
| 数据库 schema 变更 | 检查 `sql/` 目录是否有新的迁移脚本，按顺序执行 |

## 升级步骤（Docker 部署）

Docker 部署升级时沿用 [Docker 安装指导](./Docker方式安装/SkillHub安装指导.md) 中的构建和运行方式。以下命令从 **SkillHub 仓库根目录**执行：

```powershell
# 1. 停止现有容器（名称按实际部署调整）
docker stop skillhub-frontend skillhub-backend

# 2. 拉取当前分支的最新代码
git pull --ff-only

# 3. 列出增量脚本，按 CHANGELOG 指定的版本顺序执行
Get-ChildItem sql/incremental -Recurse -Filter *.sql

# 示例：执行仓库中真实存在的某个脚本；升级时替换为目标版本要求的脚本
Get-Content -Raw "sql/incremental/v0.0.2.B003/openjiuwen_market/DDL/01_market_groups.sql" | mysql -u root -p openjiuwen_market
```

随后对比并更新 `.env.docker`，重新构建、启动 Backend 和 Frontend；完整命令见 [Docker 安装指导](./Docker方式安装/SkillHub安装指导.md#6-构建镜像)。

## 升级步骤（本地部署）

以下命令从 **SkillHub 仓库根目录**执行：

```powershell
# 1. 先在原终端停止 marketplace 和 frontend 进程
# 2. 拉取当前分支的最新代码
git pull --ff-only

# 3. 列出并按目标版本顺序执行 sql/incremental 下的实际脚本
Get-ChildItem sql/incremental -Recurse -Filter *.sql

# 4. 更新 marketplace 依赖
cd marketplace
uv sync

# 5. 对比并更新仓库根目录 .env 后重新启动
python main.py
```

## 升级后验证

1. marketplace 健康检查通过（`GET /api/health`）。
2. 前端页面可访问。
3. 登录、列表、详情、下载、发布流程正常。
4. 审核员入口正常。
5. 若启用在线体验，确认会话创建、SSE 输出和会话结束正常。
6. 若启用检索，确认索引加载和搜索降级策略正常。
