# 故障排查

安装部署阶段的问题（端口占用、数据库连接、对象存储 `head_bucket`、镜像拉取等）按部署方式见对应安装指导的常见问题章节：[本地安装](../../3.%20安装指导/本地安装/SkillHub安装指导.md) 第 9 节、[Docker 方式安装](../../3.%20安装指导/Docker方式安装/SkillHub安装指导.md) 第 10 节、[K8s 方式安装](../../3.%20安装指导/K8s方式安装/SkillHub安装指导.md) 第 11 节。本文聚焦服务运行期出现的问题。

## 下载失败（存储对象不存在）

**现象**：API 返回 `500 storage_error - NoSuchKey`，或 `GET /artifacts/{id}` 报 500。

**原因**：数据库中有 Skill 元数据记录，但对象存储（MinIO / OBS）中对应的 zip 文件不存在。常见于：

- Git 导入时只创建了元数据，实际文件未上传
- 对象存储被手动清理或迁移后数据丢失
- bucket 配置变更后旧文件不在新 bucket 中

**排查步骤**：

1. 确认 `MARKET_S3_ENDPOINT`、`MARKET_BUCKET_NAME` 与实际存储一致
2. 登录 MinIO 控制台，检查 `skills/{publisher_id}/{asset_id}/{version}/` 路径下是否存在 zip 文件
3. 如果文件确实丢失，可选择：
    - 重新通过 Git 源同步或 CLI 重新发布该 Skill
    - 如果不再需要该 Skill，通过 `DELETE /plugins/{asset_id}/versions/all` 清理元数据

## 下载失败（预签名 URL 过期）

- 预签名 URL 默认约 30 分钟有效（`MARKET_S3_PRESIGNED_EXPIRES`），过期后重新获取下载链接即可。
- 反复失败时检查对象存储地址是否可被浏览器或 CLI 访问，见 [对象存储配置](./对象存储配置.md)「网络要求」一节。

## 发布失败

- 检查 zip 包结构、`SKILL.md`、版本号和图标格式
- 检查 `X-Checksum-SHA256` 是否匹配
- 若启用系统审查，检查模型配置和服务可达性

## OAuth 登录失败

排查清单见 [OAuth 登录配置](./OAuth登录配置.md)「验证与排查」一节。

## 在线体验失败

- 确认 `PLAYGROUND_ENABLED=true`（默认 `false`，路由不注册）
- 检查 marketplace 是否能访问 skill-runner（`SKILL_RUNNER_URL`）
- 检查 skill-runner 是否已启动
- 检查 worker 镜像、K8s 权限、LLM 配置和 Redis 配置
- 如何确认在线体验是否启用：前端 Skill 详情页是否有「试用」按钮；或检查 `.env` 中 `PLAYGROUND_ENABLED` 的值

## 前端接口 502 或空白（生产部署）

- 检查 Nginx 代理配置，`/api/v1` 是否正确转发到 marketplace
- 确认 marketplace 健康检查正常
- 本地开发的 Vite 代理问题见[本地安装 - 常见问题](../../3.%20安装指导/本地安装/SkillHub安装指导.md)第 9 节

## 检索无结果

检索排障（索引未就绪、Embedding 配置错误、多实例索引不同步等）见所用安装方式的常见问题「检索问题」部分：本地安装第 9 节 / Docker 方式安装第 10 节 / K8s 方式安装第 11 节。

## CLI 连不上市场

- 检查 `TEAMSKILLS_HUB_URL` 环境变量或 CLI 配置文件中的 base URL
- 自建实例需确保网络可达
- 确认 CLI 版本与 marketplace API 版本兼容
