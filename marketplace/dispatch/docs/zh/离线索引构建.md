# 离线索引构建

## 目标

`indexing/` 负责离线 progressive tree 索引构建。

输入可以是本地 skill/plugin 目录、远端 zip 物料，或预扫描 JSONL；输出是在线检索和编排侧消费的索引产物。

## 主要产物

- `tree_index.yaml`：能力树结构。
- `catalog.jsonl`：叶子节点对应的检索 payload。
- `manifest.json`：构建输入、模式、数量和配置摘要。
- `tree_index.html`：可选的能力树可视化页面。

## 目录职责

`indexing/` 当前按领域职责拆分：

- `tree/`：离线能力树构建域，包括 tree schema、LLM 构树、分组、修复、根分类、可视化等能力树相关逻辑。
- `io/`：artifact/config 文件读写，包括 tree、catalog、manifest、items JSONL 和配置文件的序列化与反序列化。
- `workflows/`：构建流程编排，包括全量构建、增量构建、输入物料解析、局部子树重建和输出写入。
- `scanners/`：skill/plugin 物料扫描，把不同来源的目录归一化成构建输入。
- `models.py`：构建产物文件名和 `CatalogRecord` 等轻量数据模型。

## 树构建算子

`tree/builder.py` 是对外 tree builder facade，负责配置装配和 public entrypoint。

其他文件按算子职责命名：

- `runtime.py`：构建主循环、进度条、审计恢复、skill profile 归一化。
- `adapters.py`：兼容适配方法，承接旧 builder 内部调用。
- `equivalence.py`：二级叶子节点等价分组后处理。
- `expansion_repair.py`：节点展开与确定性修复的适配方法。
- `llm_runtime.py`：模型调用、重试、缓存观测和 JSON 解析重试。
- `grouping.py`：候选分组、分类和批量归类。
- `expansion.py`：把分组结果展开成树节点。
- `repair.py`：树结构修复、重平衡和后处理。
- `preset_writer.py`：树 preset 输出转换。
- `root_categories.py`：默认根分类和外部 root category 配置加载。
- `json_parser.py`：tree LLM 响应中的 JSON 提取。
- `search_models.py`：tree 搜索辅助数据模型。

## 构建流程

主要入口是 `workflows/index_builder.py`：

```python
from indexing.workflows.index_builder import IndexBuilder

IndexBuilder.build(
    item_paths=["/abs/path/to/skills"],
    output_dir="/abs/path/to/index",
)
```

全量构建由 `workflows/full_build.py` 编排：

1. 解析和物化输入物料。
2. 扫描 skill/plugin。
3. 调用 `tree/` 下的能力树构建算子生成 tree。
4. 生成 leaf catalog。
5. 统一写出 tree、catalog、manifest 和可选 HTML。

增量构建由 `workflows/incremental_build.py` 编排：

1. 读取已有 tree、catalog、manifest。
2. 根据 `change_count / base_catalog_count` 判断是否升级成全量构建。
3. 对 add/delete 应用确定性 patch。
4. 只检查受影响分支及其祖先分支。
5. 必要时对局部子树做 LLM rebuild。
6. 复用同一套输出写入算子写出新产物。

## 后续演进方向

`indexing/` 会继续作为离线索引构建的稳定总入口。后续如果引入 Symphony 图构建等新的索引形态，可以在 `indexing/` 下按索引类型扩展：

```text
indexing/
├── tree/
│   └── build/
├── graph/
│   └── build/
├── io/
├── scanners/
├── workflows/
└── models.py
```

- `tree/` 承载能力树索引构建。
- `graph/` 承载图索引构建。
- `io/`、`scanners/`、`workflows/` 和 `models.py` 继续承载跨索引形态复用的输入、输出、编排和轻量模型。

这样可以在不迁移 `indexing.workflows`、`indexing.models` 等 SDK 入口的前提下新增构建方式。后续如果需要把当前 tree 构建算子进一步下沉到 `tree/build/`，应通过 `indexing.tree` 保留兼容导出。

## 接口边界

本次结构优化不改变 HTTP API，也不改变 dispatch README 中公开的 SDK 入口：

- `from indexing.workflows.index_builder import IndexBuilder`
- `from indexing.workflows.artifacts import BuildConfig, BuildMethod`
- `from indexing import CatalogRecord`

因此仓内 HTTP 接口文档不需要同步调整。目录内的文件改名属于离线构建内部实现收敛。

## 依赖边界

`indexing/` 只负责产物构建，不执行在线检索。

在线检索由 `retrieval/` 负责，它读取 `indexing/` 写出的 `tree_index.yaml` 和 `catalog.jsonl`。
